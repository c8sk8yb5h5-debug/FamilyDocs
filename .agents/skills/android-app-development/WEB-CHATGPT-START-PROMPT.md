# ChatGPT 网页版 Android 开发启动指令

> 用途：在不使用 Codex、也无法调用 ChatGPT 原生 Skills 的情况下，在 ChatGPT 网页版开始一个 Android App 开发任务时，复制下方指令作为第一条消息。请确保 ChatGPT 已连接有权读取目标 GitHub 仓库的 GitHub 插件。

## 可复制的启动指令

请按本仓库的 Android 开发规范启动本次任务，不要直接开始写代码。

目标仓库：`在这里填写 owner/repository`
本次目标：`用一句话描述要实现或修复的内容`

必须按以下顺序执行：

1. 先通过已连接的 GitHub 插件读取目标仓库中的 `AGENTS.md`、`.agents/skills/android-app-development/SKILL.md`，以及该 Skill 同目录下的 `WEB-CHATGPT-START-PROMPT.md`（如果文件存在）。再读取 README、相关设计文档、源码、Gradle 配置、现有 GitHub Actions 工作流和最近提交。若无法访问仓库或文件，明确说明，不要假装已读取。
2. 确认默认分支、当前提交和相关文件路径。不要猜测工作流名称、运行 ID、构建产物链接、签名配置或仓库状态。
3. **在实现之前搜索 GitHub 上已有的成熟项目或可复用组件**。比较维护状态、许可证、Android/Gradle 兼容性、依赖、架构和与当前需求的匹配程度。先报告是否值得复用，再决定自研；不要为了完成形式而强行引入依赖。
4. 用简短清单复述本次需求、明确约束、验收标准和计划修改的文件。区分用户明确要求与尚待确认的假设。若信息足以推进，直接继续，不要反复询问非必要问题。
5. 遵循项目现有架构与设计规范。默认界面偏好为极简、清晰、有意义的交互动效；但以目标项目自己的设计规范优先，不把 FamilyDocs 专属的配色、卡片或产品规则复制到其他 App。只做实现目标所需的最小改动，不擅自增加云同步、账号、分析 SDK、广告、加密、网络服务或其他功能。
6. 修改前检查相关代码与工作流；修改后检查 diff、状态管理、持久化、权限、无障碍、触摸/滚动冲突、异常路径和对既有功能的影响。避免重写无关文件。
7. 根据项目现有方式运行相关测试、lint 和构建。若本地工具不可用，检查可用的 CI；必须读取与当前提交对应的实际日志。没有执行的测试要明确标注，不能声称通过。
8. 只有在任务要求发布可安装 APK 时才执行签名发布检查：优先复用既有签名密钥，不能为常规版本重新生成密钥；核对真实工作流使用的 Secrets 名称、Base64 解码、密钥文件、alias、密码与签名证书。不得提交或输出密钥、密码或令牌。不要仅凭文档声称签名流程已验证。
9. 只有在确实确认产物存在且可访问后，才提供 APK/Release 下载链接。报告修改文件、提交 SHA（若有）、实际测试/构建/签名状态、产物链接及尚未完成的真机检查。不得把源码 ZIP 当成 APK。
10. 不要未经明确授权就更改仓库可见性、删除用户文件、修改 Secrets/仓库设置、强推或改写历史。如果当前 ChatGPT 连接器不能直接编辑/提交文件，明确说明能力边界，并提供可执行的补救方式。

请先执行第 1–4 步，并简要报告读取到的规范、GitHub 复用搜索结果和实施计划，再继续实现。全程用中文回答，除非我另有要求。

## 每次开发的最短调用方式

如果本聊天已经确认目标仓库和本次需求，可直接发送：

`按仓库的 AGENTS.md 和 .agents/skills/android-app-development/SKILL.md 执行 Android 开发流程。先读取规范并搜索 GitHub 可复用项目，再汇报计划，然后实施、测试并核验交付物。不要猜测未验证的结果。`

## 使用边界

- 这份文件是给用户在 ChatGPT 网页版手动复制的启动指令，不会自动注册为 ChatGPT 原生 Skill，也不会因存在于 GitHub 就自动执行。
- GitHub 插件必须已连接，并且当前账户/连接器必须有权访问目标仓库。每次新聊天都应明确目标仓库和本次任务。
- 若 ChatGPT 无法调用 GitHub 插件，先要求读取相关文件或由用户提供文件；不得声称已遵循未读取的规范。
